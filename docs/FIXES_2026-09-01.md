# NiyamLens corrective pass — 1 September 2026

This note records the defects found in the SIH26034 prototype, the implemented correction, and the remaining external approval gates. It is an engineering compliance aid, not legal advice or a statutory approval.

## Fixed in code

| Area | Verified problem | Implemented correction |
|---|---|---|
| Supervisor report | Reopening a reviewed report called an undefined `statusLabel` and crashed the React tree. | Added the missing formatter, a regression browser path, and an application error boundary with recovery UI. |
| Rule 26 tobacco | The rules engine incorrectly granted the ≤10 g/10 ml exemption to tobacco. | Tobacco is now an explicit exemption carve-out; the rule matrix, seeded benchmark and edge-case tests were corrected. |
| Consumer care | An email and care keyword could pass without the Rule 6(2) address and telephone details. | Separate consumer-care office, address, telephone and email checks are required for applicable general and food profiles. |
| Printed dates | `PKD AUG 2026` was rejected and `MFD 12.08.2026` was truncated. | Month-name, month/year and full numeric date forms are extracted and evaluated. |
| Tax wording | Abbreviated `Incl. of all taxes` was treated as a hard miss. | It now produces manual review; only the encoded full wording receives an automatic pass. |
| Food scope | A PASS could be misread as complete food-law compliance. | PASS copy now says it is limited to the encoded Legal Metrology food profile and explicitly excludes FSSAI evaluation. |
| Medical-device scope | Generic LMPC declaration and typography checks could still emit pass/fail findings even though the 2025 amendment defers those requirements to the Medical Devices Rules, 2017. | Medical-device packages now bypass generic automatic declaration/geometry verdicts and require a specialist profile review. |
| Panel calibration | One image's pixel reference and glyph measurements were shared across every evidence panel and survived transforms. | Measurements are keyed by evidence-panel ID. Missing calibration on any captured panel forces review, and preprocessing/rectification invalidates that panel's calibration and OCR boxes. |
| Reference detector | Any broad green blob could resemble the calibration marker. | Candidate selection now checks rectangular fill, aspect range, size and marker-likeness; a pure regression test rejects sparse blobs. |
| Barcode geometry | Barcode scanning discarded detector corners. | Corner and bounding-box evidence is retained. Supported codes can now flatten the full package plane without a card; the UI correctly states that absolute millimetres remain unverified. |
| Encrypted exports | Large image-bearing records crashed during base64 conversion. | Encoding is chunked. New bundles use PBKDF2-SHA256 at 600,000 iterations plus AES-256-GCM; legacy v1 decryption remains supported. |
| Offline OCR | Tesseract worker, WASM and language data defaulted to public CDNs. | Worker/core assets and English, Hindi, Telugu and Tamil data are bundled under `public/ocr` and pre-cached by the service worker. OCR QA blocks all external requests. |
| Indic-script parsing | Good OCR confidence could create false violations when the deterministic parser could not interpret a predominantly Indic-script label. | Predominantly Indic-script evidence now triggers calibrated manual review instead of an automatic violation. |
| Validation CSV | A comma inside text or JSON metadata corrupted imported rows. | Added a quoted RFC-4180-style row parser with column validation and actionable errors. |
| Accuracy claims | “Field F1” measured only whether a field ID appeared, not whether its value was correct. | Renamed it “Field detection F1” and added extracted-value accuracy from optional `expectedValues` labels. |
| Dashboard | Unknown or malformed verdict statuses produced invalid reducer values. | Unknown statuses are isolated instead of mutating declared counters. |
| Supervisor form | Modal state could retain the previous record's status and reason. | State resets whenever the selected record changes. |
| Audit wording | The UI described a locally stored hash chain as immutable. | Claims now say “hash-linked local audit”; documentation states that it is neither externally anchored nor WORM storage. |
| QA portability | Browser scripts contained one developer's absolute Playwright and Edge paths. | Playwright is a project dependency; browser selection uses the optional `NIYAMLENS_BROWSER_PATH` environment variable. |

## Verified baseline

- `npm test`: 37/37 tests pass.
- `npm run build`: production Vite build passes.
- `npm run qa:ui`: upload, perspective correction, structured extraction, violation and compliant packets, report generation, supervisor override, report reopen, validation lab, blind challenge and mobile navigation pass with zero page/console errors.
- `npm run qa:ocr`: bundled OCR completes with all external requests blocked; the sample scene produces 91% OCR confidence, 9 parsed signals and 9 mapped evidence regions.

## Still requires external validation

These are not unresolved coding defects. They are the real boundary between a competition prototype and an enforcement system:

1. The Department of Consumer Affairs or qualified Legal Metrology counsel must approve the amendment-complete rule matrix and package classifications.
2. A Legal Metrology laboratory must measure phone-camera, reference-marker, curved-panel and barcode-plane error across representative devices.
3. Inspectors must label a sufficiently large real-package dataset before the team claims field accuracy, false-violation rate or language coverage.
4. Production deployment needs departmental identity, server-side authorization, retention controls, external audit anchoring and key management.
5. Hindi, Telugu and Tamil OCR is offline-capable, but full deterministic declaration parsing in those scripts remains a future rule-pack expansion; the current safe behavior is manual review.

Do not describe NiyamLens as issuing a statutory determination. Describe it as evidence-first decision support with deterministic rules, uncertainty-aware abstention and explicit approval gates.
