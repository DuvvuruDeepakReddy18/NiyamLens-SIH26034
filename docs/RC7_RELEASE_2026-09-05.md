# NiyamLens RC7 — capture-first and review integrity

Prepared 5 September 2026. Application 0.4.5; evaluation pack `LMPC-RC-2026.09-RC7`.

## What this release changes

1. **Read a declaration before scanning the whole package.** After upload, choose MRP, net quantity or pack date, then select opposite corners of the complete heading/value/unit. The scan controls receive keyboard focus. No heading or answer is injected into OCR. Without a reading, the interface says “Not read yet,” not “absent.”
2. **Pending previews are protected.** Append or dismiss a Tesseract/Paddle crop preview before another scan, source-image change, panel navigation, raw-pass selection or finalization. Dismissing a preview leaves the transcript unchanged. Appending an initial Tesseract crop now populates ordinary extraction suggestions while leaving confirmations false.
3. **Review decisions cannot silently move to a different value.** Editing a placement note after changing the declaration leaves placement unreviewed. Changing its source panel requires a new decision. Invalid/conflicting fields cannot gain a decisive placement.
4. **Progress reflects unresolved work.** Unreadable, uncaptured, stale and invalid fields are not completed verification. Evidence traces explain why review is pending.
5. **Compound OCR tokens stay unresolved.** Examples such as `MRP 40 / 80`, `NET QTY 5 g & 100 g`, `UNIT PRICE Rs 0.40/g/100`, and `PACKED 08/2026 + 09/2026` no longer silently become the first valid-looking value. Ordinary rupee terminators, literal tax qualifiers and separately headed declarations remain supported. Raw evidence is retained.

RC7 versions changed parser behavior, not a new legal interpretation. Old RC6 queued records require the existing explicit reassessment workflow; their original observations are retained. No database migration, account/membership change or new external OCR provider is part of this release.

- Production build passed. Existing optional OCR bundle-size/OpenCV externalization warnings remain.
- Actual Chrome on a known real development photo: upload → pre-OCR region selection → three-pass Tesseract crop → protected preview → dismiss → Paddle crop → raw append → saved draft. Original hash remained unchanged; discarded readings did not enter evidence history; no typed corrections or field confirmations; no mobile horizontal overflow.
- Actual Chrome synthetic React component test: stale placement-note editing, explicit reconfirmation, unresolved progress and invalid-choice blocking passed. This is not a real-officer study.
- Existing full-app UI regression passed on the final build: capture, quality gate, perspective, navigator, trace, report, supervisor, blind challenge, reduced motion and desktop/mobile layouts. Existing synthetic functional regression passed for draft reload, sealing, two reviews, unchanged automatic findings and search.
- Known eight-photo full-app Paddle rerun: **1/10 critical fields directly; 6/10 with automated selection of available layout suggestions**. MRP 1/3, quantity 4/5, date 1/2 in the latter mode. No wrong-valid candidate on those ten eligible fields; the sample is far too small and exposed to establish general safety or accuracy. Eight photos completed without runner errors. These are AI-provisional development references, not independent human labels.

One fixed full-image-plus-heading-crops experiment resolved only **4/10** fields with derived layout selections, versus the ordinary mode's 6/10. Conflicting observations remained unresolved. It was **not enabled automatically** and is not advertised as an OCR improvement.

## Team verification walkthrough

1. Reload the app online. Confirm the rule library shows RC7. Use a **new disposable inspection**, not an existing sealed case.
2. Upload a real declaration-bearing photo. Resolve the image-quality warning honestly. Before running whole-package OCR, click **Select MRP region**; select the complete heading and amount.
3. Click **Scan selected region**. Inspect the actual crop and all raw passes. While the preview is pending, try a new scan, rotate, change panels or finalize: these must remain unavailable. Click **Dismiss crop preview** and check that no text was added.
4. Run **Try Paddle on selected region**. Append only the raw reading or explicitly selected, visually supported layout suggestions. Never select a suggestion solely because it matches an expected answer. Verify the original hash and separate raw history.
5. For a disposable test, record placement for one value, change its working-text value and edit only the note. Placement must remain **Not located** until explicitly reconfirmed. Mark a field unreadable: progress must remain incomplete.
6. Complete genuine review, context and physical measurement before sealing. A review-required result is valid; do not invent confirmation to obtain a PASS. Existing queued RC6 evidence must be reassessed explicitly, never edited in place or discarded to clear the warning.
