# Offline workspace continuity

After an online sign-in and successful active-membership lookup, NiyamLens retains a token-free device continuity record for 24 hours. It contains the project origin, account identifier, display label, active workspace memberships, selected workspace, verification time and exact expiry. It contains no access token, refresh token, password or substitute session. Choosing another workspace is limited to the cached membership list and preserves the original verification and expiry times; the choice survives offline reload and reconnect. Offline use never extends its expiry.

When the browser reports that it is offline, this record can reopen the same account/workspace's local evidence namespace even when Supabase cannot refresh an expired session. The banner labels this **Offline local work only**, shows the expiry and explains that cloud operations require fresh verification. The local actor has officer capabilities only; a cached supervisor/admin role cannot authorize offline dispositions or assignments. Capture, analysis and export are device work. Any queued case remains untrusted local evidence until the authenticated server acknowledges it.

Some networks report online while the identity service cannot be reached. After a retryable network/timeout/service failure, **Open cached local work** offers an explicit choice using the same still-valid lease and the same hard-deny API. It is never offered after an invalid-authentication response, a denied membership or an empty successful membership result. **Recheck connection** exits local mode and repeats online session and membership verification; background Auth refresh cannot silently upgrade an explicitly opened local workspace.

On reconnection the Gate disposes the offline API, removes the cached membership from the active UI and checks the online session and current active memberships. No cached permission authorizes a server request. Revocation, missing membership, non-retryable lookup failure or a different account prevents reuse of the old offline identity. A retryable service failure can preserve the existing time limit but cannot extend it. Every offline API method rejects without obtaining headers or contacting the server. The regular managed APIs still enforce their own authentication and authorization.

Explicit Sign out immediately removes the continuity record and leaves a device sign-out lock. The lock prevents a stale SDK session from silently reopening the app after an offline logout could not contact the Auth service. An explicit successful sign-in clears it. Sign-out leaves original images, drafts and the outbox in their existing local namespaces; it does not delete evidence.

The device record is not a signed authorization grant, an encrypted vault or proof of physical identity. Anyone controlling this browser profile already has access to its local evidence storage. Use it on a trusted, screen-locked device. Revocation while disconnected cannot be learned until reconnect, and the 24-hour expiry uses the device clock; clock rollback behind the verification timestamp is rejected, but a compromised device is outside this local continuity control. This feature does not claim complete PWA/offline browser compatibility on every phone.

Verification covers token-free serialization, missing/malformed/expired/wrong-project/wrong-account records, exact expiry, clock rollback, revoked membership, sign-out, replacement accounts and a hard-deny offline API. Actual browser acceptance must additionally demonstrate an expired Supabase session, offline reload and local work, then reconnect with a revoked membership; isolated tests do not establish a live provider outage trial.

## Executed isolated acceptance

`node --test tests/offline-identity.test.mjs` passed all ten tests. `node tools/qa-offline-workspace.mjs` passed in a fresh Chrome context against the managed production build using disposable mocked Auth/membership responses. It selected the second of two authorized workspaces, expired the test SDK session, disabled network transport and reloaded through the real service worker. On this machine Chrome still reported `navigator.onLine: true` after that reload, so the test used the actual **Open cached local work** button after the retryable verification timeout; it did not override the navigator value. The same second workspace remained selected across reload, fallback, successful membership revalidation and a subsequent offline transition.

The browser then uploaded the controlled PNG fixture, entered a clearly manual test transcript, sealed a local pending case and downloaded its original-image JSON evidence with `syncState: pending` without any cloud call during the local workflow. It verified the **Local work only** header, cached supervisor's offline officer role and disabled cloud actions, returned a revoked membership on reconnect and observed denied workspace access, then verified that an explicit offline sign-out left the lease absent and the sign-out lock intact after reload. No browser page errors occurred. This is workflow and authorization-boundary evidence using mocked server responses, not a live Supabase outage, an OCR accuracy measurement or target-phone acceptance.
