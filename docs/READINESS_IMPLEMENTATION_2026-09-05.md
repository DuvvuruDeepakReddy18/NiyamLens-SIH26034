## Fresh recognition diagnostic: the main unresolved problem

The actual local Chrome pipeline was run 16 times on eight already-used, deliberately difficult development photographs, with no manual transcript corrections. Against ten readable critical fields with provisional AI reference labels:

| Raw workflow | Exact critical-field recovery | Runtime completion |
|---|---:|---:|
| Standard three-pass browser OCR plus extraction | 0/10 | 8/8 photographs |
| Whole-image Paddle raw preview plus extraction | 1/10 | 8/8 photographs |

This is **not general accuracy**, not a human-labelled holdout and not legal-verdict accuracy. It measures both OCR and heading/value association. Some correct words and numbers occur in Paddle's transcript but are not safely associated with the correct declaration. These runs did not evaluate guided crops, reviewed spatial proposals or officer corrections. The exact measured build fingerprint, all raw text, field denominators and limitations are retained in [the diagnostic report](../reports/readiness-2026-09-05/ACTUAL-BROWSER-DEVELOPMENT-OCR.md).

Consequently, adding another model or demonstrating that buttons work does not yet solve recognition. Preserve this baseline. Test a separately labelled guided-crop/spatial-association workflow next, without tuning on the reserved set. A genuinely useful system must reduce the total work needed for a correct report, not simply require the operator to retype everything.

## Release decision

The prototype has stronger failure handling, safer rule boundaries and a simpler operator path. **It is not yet justified to call it winner-ready, field-validated or generally accurate.** The remaining release gates are independent recognition labels/results, useful end-to-end field performance, qualified legal/measurement review, target-device and real hosted acceptance, and verification of the exact deployed revision after an authorized release.
