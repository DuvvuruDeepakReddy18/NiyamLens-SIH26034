## Recognition is still the main product weakness

The fresh built-app run on eight **known development photos**, using ten AI-provisional readable references, recovered **1/10 directly** and **5/10 after automation selected available layout suggestions**. Five fields remained unresolved; zero eligible wrong-valid derived readings were observed in this tiny set. These are not blind accuracy, calibrated safety or real officer verification.

The 24 previously reserved web photos are now AI-exposed. Only five of their 72 target slots were readable; 64 were not visible and three were illegible. Do not tune on them or rebrand the AI review as Arif's and Tharun's independent labels.

## Release safeguards and rollback boundary

The old live functions were inspected and compared with the new bodies. The only body differences were business error codes and formatting. The migration was first run in a transaction ending in ROLLBACK; all original definitions and the inspected execute permissions matched on readback. The compatible RC6 API was promoted before the migration was committed. A subsequent live readback confirmed PT409 and denied anon/authenticated execution.

Function-only rollback artifacts are Git-ignored under `.niyamlens-private/releases/rc6-conflict-20260905-v2/`. SQL migration digest: `9233514b1de6fa275ddd9bcd18982f03d698b216b685c7e76cf93e4b8db47088`. Exact old-definition rollback digest: `724a58361b0707aeb5f7581c1cf6413cd7785e22d8a2c63d1b0188ac41b1d751`.

**These are not a full workspace/Auth/Storage backup or protected off-site copy.** Follow [the separate backup/restore protocol](BACKUP_RESTORE.md) for those tasks. The prior deployment `dpl_44QkVJ3UN6MEjcYny9aeuTpRYdai` remains available, but do not blindly downgrade after RC6 cases exist: verify case/rule compatibility and preserve queues first. A failed save/retrieval, accepted unauthorized access or repeated health failure requires an explicit release review; no automated rollback was installed.

The SQL change was applied through the authenticated CLI as a guarded transaction, with private receipts. This does not claim Supabase migration-history repair or a full live schema reconciliation. Use the receipts and inspect migration history before any future automated database push.
